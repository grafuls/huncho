# GPU setup

Install the `huncho` RPM for both CPU and CUDA. Run `huncho` on either host:

```bash
sudo dnf copr enable <owner>/huncho
sudo dnf install huncho
huncho serve --model Cloudflare/clef
```

These instructions describe the unified package built from this repository.
Publishing it requires rebuilding the RPM and updating the COPR configuration;
see [RPM packaging](../packaging/rpm/README.md). Existing published packages
may still use the previous separate `huncho` / `huncho-cuda` layout.

The default `HUNCHO_DEVICE=auto` selects CUDA for Kev and Clef when GPU 0 passes an
initialization and kernel probe, otherwise CPU. No NVIDIA software is required
on CPU hosts. Use `huncho` in existing scripts that called `huncho-cuda`.
ModernBERT and F3 Qwen retain CPU defaults, including `auto`. Their newly wired
CUDA loaders require explicit `HUNCHO_DEVICE=cuda` / `cuda:N` and labeled
startup qualification; full released Laya/Nimble GPU validation remains pending.
ModernBERT executes FP32; F3 honors supported requested precision. ONNX GPU
EP registration remains pending. `HUNCHO_CLEF_DEVICE` remains a legacy alias
for Kev/Clef;
`HUNCHO_DEVICE` takes precedence.

## GPU requirements

- A compatible NVIDIA GPU and installed driver. The default RPM targets
  `sm_80` (Ampere). Turing GPUs such as the T4 need an `sm_75` build; see
  [RPM build overrides](../packaging/rpm/README.md). The driver must also be
  able to load the PTX generated by the selected toolkit.
- CUDA runtime libraries matching the toolkit used to build the package. A
  CUDA 13 build uses `libcuda.so.1` from the driver and CUDA runtime libraries
  including `libcublas.so.13` and `libcurand.so.10`. Install the corresponding
  runtime packages from NVIDIA's repository for your distro. The full toolkit
  is needed to build Huncho, but not to run it.
- Enough VRAM for the whole model on one GPU. Clef has approximately 54 GB of
  BF16 weights before working memory; use an 80 GB GPU for this checkpoint.
  There is no multi-GPU sharding or quantization. A 24 GB or 48 GB GPU cannot
  fit the full weights. On CPU the model needs substantial system RAM instead.

Missing libraries, driver failures, and kernel incompatibility cause automatic
CPU fallback. Out-of-memory or model errors after selection are reported and
do not retry inference on CPU. A CPU fallback for the full 27B checkpoint is
slow and still needs enough RAM.

Kev-4B uses FP16 on CUDA, with FP32 pointer projections. Source weights and
LoRA merging are staged in system RAM before transfer to the GPU. Keep enough
system RAM for the checkpoint as well as GPU memory for weights and inference.
Kev supports an 8,192-token complete row. Request-local prefix caching and
question batching are implemented as opt-in paths, but their native CUDA FP16
variants failed probability parity; keep them disabled for this variant.
Experimental kernel profiles require separate qualification. Multi-GPU
sharding and quantization remain pending. See
[optimization validation](kev-optimization-validation.md).

See [Kev T4 validation](kev-cuda-validation.md) for tested versions, numerical
agreement, and measured memory use with the full Kev-4B checkpoint.

## Overrides and service

```bash
# Automatic CUDA selection, otherwise CPU:
huncho serve --model Cloudflare/clef

# Kev on CUDA (FP16 by default):
HUNCHO_DEVICE=cuda huncho serve --model jaredpalmer/kev-4b

# Require CUDA; report the underlying error if unavailable:
HUNCHO_DEVICE=cuda huncho serve --model Cloudflare/clef

# Select a different visible GPU:
HUNCHO_DEVICE=cuda:1 huncho serve --model Cloudflare/clef

# Force CPU, without probing or loading NVIDIA libraries:
HUNCHO_DEVICE=cpu huncho serve --model Cloudflare/clef
```

The unified package includes `huncho.service`, `/etc/huncho/huncho.env`, the
`huncho` service user, and `/var/lib/huncho` for cached models. Set
`HUNCHO_DEVICE` in that environment file. To serve Clef instead of the
bundled mock, use `sudo systemctl edit huncho` and add:

```ini
[Service]
ExecStart=
ExecStart=/usr/bin/huncho serve --model Cloudflare/clef
```

Then restart:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now huncho
sudo systemctl restart huncho
```

A CUDA-capable buildroot must have NVIDIA's toolkit repository enabled. For a
local build, see [Clef build and run](clef.md). For service, authentication, and
cache configuration, see [Operations](operations.md).

## Verify GPU use

```bash
nvidia-smi
journalctl -u huncho -f
```

At startup, `huncho serve` reports each registered model as `on CPU` or
`on GPU (CUDA device 0)` (with the selected GPU's number). The Clef loading log
also reports the device and dtype: BF16 on Ampere or newer CUDA GPUs, FP16 on
Turing and CPU. The CUDA probe uses FP16 so a lack of native BF16 does not
cause CPU fallback. `--dtype` overrides remain available; BF16 requires
CUDA compute capability 8.0 or newer.

To diagnose automatic fallback, retry with `HUNCHO_DEVICE=cuda` to expose
the initialization or library-loading error. The public command is a launcher;
inspect the private GPU executable for missing libraries:

```bash
ldd /usr/libexec/huncho/huncho-cuda
```

## Performance and conformance

This port recomputes the 27B backbone on each request, uses unfused attention
and per-token DeltaNet recurrence, and has no quantization. Validate accuracy
and latency on your target GPU before relying on it:

```bash
HUNCHO_DEVICE=cuda huncho conform --model Cloudflare/clef --golden ./clef-golden.json
HUNCHO_DEVICE=cuda huncho bench --model Cloudflare/clef
```

The full Cloudflare checkpoint and CUDA inference have not been validated in
the development environment used for this change. See [Clef limits](clef.md).
